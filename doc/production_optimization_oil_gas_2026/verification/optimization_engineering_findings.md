# Engineering interpretation of the revised examples

This note supplements the executable-fence ledger. A successful interpreter run does not by itself establish a qualified engineering model.

- **Current optimizer behavior:** the book now describes full-model final-point replay, explicit feasibility acceptance, narrow plant evidence scope, expected-equipment utilization coverage, and the boundary between agent actions in a simulator and approved operational changes.
- **Compressor screening:** `autoSize(1.2)` means a multiplicative factor. Generated curves are synthetic screening data. Simple throughput examples reset chart/solve-speed modes and retain a declared power constraint; vendor-map utilization is a different evidence requirement. `getPolytropicFluidHead()` reports the solved fluid head in kJ/kg.
- **VFP semantics:** upward production hydraulics requires an upstream pressure solve. A process capacity or required process-inlet-pressure table is not automatically a reservoir simulator well-BHP deck. The revised Java and Python examples export process-screening diagnostics when that is their actual scope.
- **Automation:** model input addresses must exist and be writable. Chapter30 now uses the actual single-process feed and compressor addresses; its bounded optimizer returned a feasible result. A separator's operating pressure is not Reid vapor pressure, and a reported gas temperature is not a dew-point test.
- **Calibration units:** at the audited source revision, `BatchParameterEstimator.buildFunction()` registers measurement paths without forwarding the stored unit metadata. The Chapter32 temperature recovery example therefore supplies native kelvin observations. Its synthetic known-efficiency recovery passes with chi-square approximately 1.18e-10. This is a software recovery exercise, not independent plant validation.
- **JSON bounds:** the evaluator problem definition can include infinite inequality bounds. The Chapter32 exporter converts these to explicit JSON null values and records that encoding, rather than emitting invalid numeric JSON.
- **SQP acceptance:** the demonstrated SQP run can return a power-feasible candidate while convergence remains false. The manuscript explicitly rejects that candidate and retains a separately solved feasible baseline instead of presenting an unqualified optimum.
- **NGL train:** the old one-sided HeatExchanger produced an implausible near-absolute-zero expander outlet. Explicit Cooler precooling gives a physically plausible upstream case. At -30°C precooling, the illustrated case produces 6.43 MSm3/day residue gas with an expander outlet near -76.8°C and approximately 6.4 MW gas compression. These values exclude cooling and fractionation duties.
- **Fractionation:** the included full deethanizer examples report `solved() == False`. Their product values are diagnostic and excluded from accepted plant predictions. A bounded 30-tray AUTO probe encountered the 512 MB worker heap limit. Any replacement stabilizer experiment is a separate study with its own acceptance gate.
- **State archives:** full ProcessModelState capture can fail for the selected column internals because a separator thermodynamic system is absent. The example records the exception as a diagnostic and does not claim a restorable full-plant state.
- **Dynamics:** Chapter29 demonstrates controller and transient API use, while inventory/balance validation remains a separate requirement. Its illustrative notebook control model is not represented as a NeqSim transient benchmark.
- **Gas quality:** ISO 6976 Wobbe values use explicit reference temperatures and kJ-to-MJ conversion. The hydrogen study does not infer flame propagation from thermodynamic density, and a single CO2/oil flash does not determine multicontact minimum miscibility pressure.
